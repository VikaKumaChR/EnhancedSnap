# 已知限制

[README](../README.zh-TW.md) · [English](LIMITATIONS.md)

Enhanced Snap 做不到或與 Windows 貼齊不同的地方，以及原因。

- **以系統管理員身分執行的應用程式**：這類視窗（系統管理員終端機、工作管理員）只有提升權限的程序才能移動。
  開啟「貼齊以系統管理員身分執行的應用程式」：Windows 只詢問一次，之後由排程工作以系統管理員權限啟動 Enhanced Snap（登入時也是）。
  您的帳戶需為系統管理員，且需使用安裝程式或免安裝版：Microsoft Store 版無法以系統管理員權限啟動，因此不會移動這些視窗。
- **Windows 設定中的「貼齊視窗」顯示為關閉**：開啟「取代 Windows 貼齊」時，Enhanced Snap 執行期間這個開關會顯示為**關閉**——這就是接手；
  暫停或結束 Enhanced Snap 會自動重新開啟。若程式被強制結束導致仍為關閉，啟動一次 Enhanced Snap（或執行 `EnhancedSnap.exe --restore-snap`）即可還原。
  Microsoft Store 版不會把這項變更寫入您的設定檔，因此登出也會還原 Windows 貼齊。
- **整個程序共用同一個 ID 的應用程式**：工作列預覽依應用程式的 AppUserModelID 找到它的按鈕。為整個程序設定此 ID 的應用程式
  （例如 VS Code 與部分 Electron 應用程式）無法從外部比對，因此它們的工作列預覽不會顯示群組，只由這類應用程式組成的群組
  也不會出現在 Alt + Tab 與工作檢視中；群組的其他功能不受影響。
- **群組縮圖是靜態畫面**：Alt + Tab 與工作檢視中的群組縮圖是群組最後一次變動或使用時的畫面，不像 Windows 原生群組那樣即時更新
  （預覽則是在開始時擷取）。
- **工作列預覽中的群組順序**：在應用程式的工作列預覽中，群組排在該應用程式的視窗之後：Windows 依視窗開啟的順序排列，
  而其他程式唯一能調整順序的方式（移除再重新加入視窗）會清除那些視窗的徽章與進度列。從群組的視窗按 Alt + Tab 或 Win + Tab 時，
  群組會排在第一個；以滑鼠或觸控板手勢開啟工作檢視時，則依群組最後一次使用的時間排列。
- **「關閉所有視窗」也會傳到群組**：在應用程式工作列按鈕上選「關閉所有視窗」，也會傳到歸在該按鈕下的群組預覽，
  因此該應用程式所在群組的所有視窗（包括其他應用程式的視窗）也會被要求關閉。
- **不使用標準移動迴圈的應用程式**：不使用標準 Windows 移動迴圈的拖曳（例如把瀏覽器**分頁**拖出來、部分遊戲與遠端桌面用戶端）
  不會顯示區域。
